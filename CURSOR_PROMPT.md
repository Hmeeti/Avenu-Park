## 1. ТЕХНИЧЕСКИЕ РАМКИ (жёстко)

- **Стек:** чистые HTML + CSS + JavaScript (ES2020), **без фреймворков, без сборщика, без npm-зависимостей**. Должно открываться просто двойным кликом по `index.html` и работать на **GitHub Pages** (в подпапке репозитория).

- **Данные меню НЕ через `fetch('menu.json')`** (не работает при открытии с `file://` и в некоторых режимах Safari). Храни данные в `data/menu.js` как обычный скрипт: `window.MENU_DATA = {...}`. Подключай его обычным `<script defer>`.

- Структура проекта:

## 2. ФУНКЦИИ (по образцу референса)

1. **Экран приветствия / шапка**: эмблема + логотип, название, подпись «Hotel & Cafe», кнопки «Меню», «Информация».
2. **Переключатель языка: RU / KZ / EN.** Выбор сохраняется. Переводится и интерфейс, и названия/описания блюд (см. схему данных: поля `ru`, `kk`, `en`). Если перевода нет — показывать русский, а не пустоту. Атрибут `<html lang>` меняется вместе с языком.
3. **Переключатель темы: светлая / тёмная.** По умолчанию — светлая (фирменная бежевая). Выбор сохраняется; если пользователь ничего не выбирал — уважать `prefers-color-scheme`. `<meta name="theme-color">` меняется вместе с темой.
4. **Кухня / Бар**: верхний переключатель групп (см. раздел 4). **Разделы меню**: липкая (sticky) горизонтальная лента категорий-«чипов» со **scroll-spy** (активная категория подсвечивается при прокрутке, лента сама подскролливается к активному чипу). Тап по чипу — плавная прокрутка к разделу с учётом высоты липкой шапки.
5. **Кнопка «Разделы»** — bottom-sheet со списком всех категорий (быстрая навигация).
6. **Поиск** по названию, составу и категории (на всех языках; регистронезависимо; `ё=е`; debounce 150 мс; подсветка совпадений; понятный empty-state «Ничего не найдено»; кнопка «×» очистки).
7. **Карточка блюда**: фото, название, краткое описание/состав, выход (г/мл), цена, кнопка «+».
   Тап по карточке открывает **bottom-sheet с деталями (тех-карта)**: большое фото, полный состав, выход, КБЖУ (если есть в данных), аллергены/пометки, цена, счётчик «− 1 +».
8. **Счёт-калькулятор (без реальной отправки заказа!)**: гость набирает блюда и видит сумму. Плавающая нижняя панель «Счёт · N поз. · сумма ₸» → открывает панель счёта:
   - поле **«Стол №»**,
   - список позиций со степпером «− N +» и кнопкой удаления,
   - строки: **Сумма → Обслуживание X% → Итого** (процент берётся из `config.js`; если процент = 0, строка «Обслуживание» скрывается),
   - **«Разделить счёт»**: выбор числа гостей (2–20) → «с человека: N ₸» (округление вверх до 10 ₸, показывать, что округлено),
   - **«Выбрать официанта»**: список имён из `config.js`; выбранное имя показывается в счёте (если список пуст — кнопка скрыта),
   - **«Очистить»** с подтверждением.
   - Состояние счёта сохраняется в `localStorage` (ключи с префиксом `pa_`), переживает перезагрузку.
   - **Всё обёрнуто в try/catch**: в приватном режиме Safari `localStorage` может бросать исключение — сайт обязан работать и без него.
9. **Раздел «Информация»** (аналог «Правила заведения»): Wi-Fi, время завтраков, заезд/выезд, контакты, адрес, график, правила. Данные из `config.js`; пустые блоки не выводить.
10. **Кнопка «Наверх»** (появляется после прокрутки ~600 px).
11. **Метки блюд**: `hit` (Хит), `new` (Новинка), `veg` (Вегетарианское), `spicy` (Острое), `halal`. Показываются маленькими бейджами только если заданы в данных.
12. **Блюдо «нет в наличии»** (`available:false`): затемнено, подпись «Нет в наличии», кнопка «+» отключена.
13. Ссылки на Instagram / телефон (`tel:`) / карту в подвале.

## 6. MOBILE-FIRST И SAFARI/CHROME — ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`. Не блокировать зум (`user-scalable=no` не использовать).
- Safe-area: `padding-bottom: env(safe-area-inset-bottom)` для нижней панели счёта и bottom-sheet, `padding-top: env(safe-area-inset-top)` для шапки.
- Высота: `100vh` + переопределение `100dvh` через `@supports`. Не использовать `100vh` для bottom-sheet без фолбэка (адресная строка Safari).
- Липкие элементы: `position: sticky; top: 0` вместе с `-webkit-sticky`. Проверить, что ни у одного предка нет `overflow: hidden`, ломающего sticky.
- Поля ввода (поиск, номер стола): `font-size: 16px` минимум — иначе iOS Safari приближает страницу при фокусе. `inputmode="search"` / `inputmode="numeric"`.
- Открытие bottom-sheet/модалок: блокировать прокрутку фона корректно для iOS (класс на `body` + сохранение/восстановление `scrollY`, не просто `overflow:hidden`). Закрытие — по тапу на подложку, по кнопке «×», по жесту свайпа вниз (простая реализация) и по клавише Esc. Фокус-ловушка и возврат фокуса.
- Кнопка «Назад» на Android: закрывает открытую панель (через `history.pushState`/`popstate`), а не уходит со страницы.
- Тач: зоны нажатия ≥ 44×44 px, `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation` (убирает задержку двойного тапа), `:active`-состояния у кнопок.
- Горизонтальная лента чипов: `overflow-x: auto`, `-webkit-overflow-scrolling: touch`, скрытый scrollbar, `scroll-snap` опционально; **на странице не должно быть горизонтальной прокрутки ни на одной ширине от 320 px**.
- Плавный скролл: `scroll-behavior: smooth` + JS-фолбэк через `window.scrollTo({top, behavior:'smooth'})` с проверкой поддержки. Scroll-spy — через `IntersectionObserver` (без тяжёлых scroll-обработчиков; `passive: true` там, где скролл-слушатели неизбежны).
- Шрифты и картинки не должны вызывать сдвиг вёрстки (CLS < 0.05).
- Не полагаться на `hover` — всё работает на тапе.
- Длинные названия и описания переносятся (`overflow-wrap: anywhere` там, где нужно), карточки не «ломаются» при 2–3 строках названия и на казахском/английском языке.
- Жёстко избегать: `100vw` (даёт горизонтальный скролл из-за scrollbar на десктопе), `position: fixed` внутри трансформируемых родителей, `gap` в старых flex-сценариях без проверки, `:focus` без `:focus-visible`.
